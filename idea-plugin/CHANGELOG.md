# Changelog

## 0.1.23

- 恢复语法高亮：diff 内容重新带上 FileType（日志已证明 284ms 的耗时是一次重建原生 viewer 的固定成本，和带不带 FileType 无关）
- 修「凭空多出来的空行」：补丁回放改成和 `git apply` 一样严格——每个 hunk 的上下文/删除行都要和当前文件逐字对上、行数要等于 hunk 头声明，对不上就整份放弃、退回只显示补丁片段（不再把错位的行拼进「改后」文本）；同时保留原文件行尾（原来改前 CRLF、改后 LF）
- 打开预览对话框时就在后台把每个文件的「改前/改后」文本全部准备好，点击时 EDT 上只剩一次 setRequest，不再有「点击→后台排队→读文件→再渲染」的链路；合并窗口 30ms
- 耗时日志细化成「构造请求 / setRequest / 总耗时」，超过 60ms 才记一条

## 0.1.22

- 对齐官方实现：diff 内容不再带 FileType（官方 VCS diff 用的是纯 DocumentContent，不带语言类型，编辑器不会为它建 PSI）。带 Java 类型时每次重建 viewer 都要给两个文档建代码高亮 + 语法分析，单次可卡 EDT 数百毫秒——这是历次「点了没反应」的主因
- 回退 0.1.21 的多面板缓存：平台 `DiffRequestProcessor.doApplyRequest` 每次 setRequest 必然销毁旧 viewer 重建，多留几个面板只会让多个编辑器同时跑守护进程，实测更卡；恢复单一 DiffRequestPanel
- 点击合并窗口 120ms → 30ms，点击后几乎立刻切换
- 渲染耗时超过 80ms 会写一条 warn 到 idea.log，便于继续定位

## 0.1.21

- 文件列表行高被 BoxLayout 拉高的问题：每个文件行锁定 24px 行高，多余空间交给底部 glue，不再出现「3 个文件却每个占 60 多像素、中间大片留白」
- 滚动条：明确按需显示（此前可能被隐藏导致滚不动），条宽由 7px 调到 8px，列表和 diff 区都能滚
- 原生 diff 改为「按文件缓存面板」（LRU 3 个）：来回点已看过的文件直接换卡片，不再每次 setRequest 重建两个编辑器，连续点击不再越点越卡
- 对话框关闭时统一 dispose 所有缓存的原生面板

## 0.1.20

- 预览对话框关闭后仍可再次查看：预演结果按「配方 + HEAD + 工作区状态」缓存，签名一致时再次点击深度修复直接复现上次预览，不再重跑 Maven + OpenRewrite（对话框里会注明"复用上次预演结果"）
- 深度修复真正执行后缓存自动作废，避免用旧补丁
- 修复原生模式偶发卡顿 1 秒：去掉 49 个文件的后台批量预读（批量 loadText 持读锁，偶尔与 EDT 写动作相撞），改为按需单次读取
- 渲染单飞增加异常兜底：同步异常也会释放标记，不会让后续点击被永久排队

## 0.1.19

- 修复原生模式连续点击时「点了没反应、过一会才跳」：渲染改为单飞（一次只跑一个），中途的点击合并成一次待渲染，不再把多次 `setRequest` 排进 EDT 队列
- 点击时立即更新文件路径与 `+n / -m` 标题，选中行高亮即时跟随，不必等对比渲染完
- 原生内容改用「文件类型」创建轻量文档，不再绑定真实 VirtualFile：避免编辑器把改后文本当真实文件建 PSI（整文件重新解析，单次点击会卡 EDT 数百毫秒）

## 0.1.18

- 修复原生模式下连续点击条目卡顿：点击加 120ms 防抖，快速连点只渲染最后一次，避免每点一次就重建一套原生编辑器把 EDT 排满
- 原生模式增加按文件缓存（改前/改后文本），打开预览时后台预热全部文件，点已看过的文件不再读盘、不再重套补丁

## 0.1.17

- 预览对话框新增「原生对比」渲染：内嵌平台 `DiffRequestPanel`（真实编辑器，虚拟化 + 增量重绘 + 语法高亮），由 `preview.nativeDiff` 开关控制，默认开启
- 原生模式按补丁 hunk 的行号把改动还原成整文件的「改前 / 改后」再对比，行号、上下文、语法高亮与 IDEA 自己的对比窗口一致；hunk 行号对不上时退化为片段对比
- 原生面板用反射构造，任一环节失败（类缺失、构造失败、请求渲染异常）自动回退内置自绘列表，不会让预览对话框打不开
- 对话框未显示时先缓存待渲染请求，等 window 就绪再渲染，避免拿不到 Window 导致面板创建失败

## 0.1.16

- 修复统一视图不满宽：内容窄于视口时列表跟随视口宽度，行底色铺满整块区域（原来只有文字那么宽）
- 修复中文乱码：patch / 命令输出先按 UTF-8 严格解码，遇到非法字节回退 GB18030，GBK 源码项目的中文注释不再显示为乱码
- 继续优化点击响应：打开预览时就在后台把所有文件的 diff 行数据预处理完，点击条目只剩一次内存赋值；行配色常量提到绘制外，不再每次绘制 new JBColor（JBColor 构造会登记进全局主题更新表）

## 0.1.15

- diff 区域从 `JTextPane` 改为固定行高的自绘列表：只绘制可见行，不再有文档整体排版，切换/点击文件即时响应
- 修复并排视图两栏逐行错位（表现为「统一和并排内容不一致」）：长行不再按宽度折行，左右两栏固定行高、行数严格一致，缺失侧用空白行占位
- 统一 / 并排共用同一份行数据模型，切换视图不再重新构建（原来每种模式各自缓存一份文档）
- 文件路径与改动行数（+n / -m）上移到 diff 区顶部固定标题，两种视图都显示，不再作为正文第一行
- 支持右键「复制此行 / 复制全部」；并排模式左右两栏选中同一行

## 0.1.14

- 修复预览对话框 diff 区域「全是空白」：后台线程渲染完成后用 `invokeLater` 默认的 `NON_MODAL` 模态状态投递，会被模态的预览对话框一直挡在队列里不执行；改为 `ModalityState.any()` 投递，并加上失败后回退到 EDT 同步渲染的兜底

## 0.1.13
